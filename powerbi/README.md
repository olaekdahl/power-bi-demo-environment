# PL-300 Demo Power BI Solution

A Power BI Project (`.pbip`) with five pages over a five-table model. Generated by
[`../scripts/generate-pbip.py`](../scripts/generate-pbip.py) — **edit the generator,
not these files**, then regenerate.

```bash
./scripts/export-spatial-csv.sh                  # pull the geography views off the VM
python scripts/generate-pbip.py --out powerbi --sql-dir .spatial-export
python scripts/validate-pbip.py powerbi          # checks against Microsoft's schemas
```

The export step is what makes this reproducible: the spatial tables are
materialised from the live SQL views, so a rebuilt environment regenerates the same
solution instead of depending on CSVs somebody produced by hand. Regenerating is
idempotent — it produces byte-identical output and leaves this README alone.

Open `PL300-Demos.pbip` in Power BI Desktop on the demo VM. Use **File → Save as** to
produce a single-file `.pbix` if you want one artifact to hand out.

## The model

Five tables, all **inline M `#table` literals** — so the file opens with no data
source prompt and no credential setup, which is what makes it safe to hand to a
class and possible to validate automatically.

| Table | Rows | Source |
|---|---|---|
| `CategorySales` | 4 | Contoso CSV, aggregated |
| `MonthlyRevenue` | 12 | Contoso CSV, aggregated |
| `CategoryMonthlySales` | 48 | Contoso CSV, aggregated |
| `StoreGeography` | 8 | **SQL** `dbo.vw_StoreLocations` + `dbo.vw_StoreCatchment` |
| `CustomerGeography` | 480 | **SQL** `dbo.vw_CustomerLocations` |

The two spatial tables are the real output of the SQL Server `geography` views in
the `PL300Demo` database. To read them live from SQL instead of from the inline
literals, follow [`LIVE-SQL-QUERIES.md`](LIVE-SQL-QUERIES.md) — one `Source` step
per query.

`MonthName` carries `sortByColumn: MonthNumber`, without which a text month sorts
alphabetically and the axis reads April, August, December…

## Making the R and Python visuals render

The script bodies are in the report *and* as standalone files in
[`scripts/`](scripts/). Power BI will not load an externally-authored script body
while the report is in PBIR-Legacy form (see below), so do this once per visual:

1. Select the visual. The script editor opens at the bottom.
2. Open the matching file, copy all of it, and paste over the editor's contents
   (`Ctrl+A`, `Ctrl+V`).
3. Click the ▷ run button in the script editor header.

| Page | File |
|---|---|
| 2. Python visual | `scripts/python-category-revenue.py` |
| 3. R visual | `scripts/r-ggplot-category.R` |
| 4. R forecast | `scripts/r-forecast-arima.R` |

Expected results, confirmed on this VM: the Python and ggplot2 visuals draw four
horizontal bars with Camping highest at ≈$3.30M; the forecast visual titles itself
**ARIMA(2,0,0)** and projects 678,184 / 679,910 / 632,080 for the next three months.

The first time you open the report Power BI asks to **Enable script visuals** —
accept it. Pressing Escape *cancels* that prompt, which leaves every script visual
blank with no error message anywhere.

## Two report formats, and why

The generator emits the report twice:

- **`PL300-Demos.Report/report.json`** — PBIR-Legacy. This is what Power BI Desktop
  actually reads on a stock install, so it is what makes the solution work today.
- **`PL300-Demos.Report/definition/`** — PBIR. The documented, per-file,
  schema-validated format, ready for when you enable the preview feature.

Microsoft's own documentation is blunt about the first one: *report.json "contains
the report definition in the Power BI Report Legacy format (PBIR-Legacy) and
**doesn't support external editing**"*. That is not a stylistic warning. Hand-authored
`report.json` keeps visual types and field bindings, but Power BI silently discards
every `objects` entry — which is exactly why the R/Python script bodies do not load
and why visual titles fall back to auto-generated ones like "Revenue by MonthName".

PBIR fixes both, because `visual.json` separates the two concerns properly:

| What | Where |
|---|---|
| Visual title | `visual.visualContainerObjects.title` |
| Script body | `visual.objects.script` |

### Switching to PBIR

1. In Power BI Desktop: **File → Options and settings → Options → Preview features**
   → tick **Store reports using enhanced metadata format (PBIR)**. Restart Desktop.
2. Regenerate with `--pbir`, which sets `definition.pbir` to version `4.0`:

   ```bash
   python scripts/generate-pbip.py --out powerbi --sql-dir <...> --pbir
   ```

Do these in that order. A `version: 4.0` project on a Desktop *without* the preview
feature does not open at all — Power BI starts a blank "Untitled" report and says
nothing. That asymmetry is why `1.0` is the default.

The `definition/` folder is emitted and schema-validated either way, so
`validate-pbip.py` catches shape errors in about a second rather than one
five-minute render at a time.
